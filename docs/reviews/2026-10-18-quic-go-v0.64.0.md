# quic-go v0.64.0 maintenance upgrade

Date: 2026-10-18. Starting Jul source:
`97c1a0c09cea84e5c49759918551691502bf27fc`. Owner: [#569](https://github.com/victornife/jul/issues/569).

## Scope and compatibility

Upgrade quic-go v0.63.0 to the stable
[v0.64.0 release](https://github.com/quic-go/quic-go/releases/tag/v0.64.0),
published 2026-10-16. The [39-commit release diff](https://github.com/quic-go/quic-go/compare/v0.63.0...v0.64.0)
adds HTTP/3 header-buffer allocation hardening and QUIC congestion recovery,
reordering, MTU and candidate-path validation fixes. The header reader initially
allocates at most 8 KiB and grows with arriving data, after checking the configured
limit. These are applicable maintenance improvements independently of #569's
malformed-peer conformance residuals. No new Jul performance claim is made.

Upstream `go.mod` is identical between the two tags: Go 1.26.0 minimum and
qpack v0.6.0. Jul remains on Go 1.27.2 and qpack v0.6.0. `go mod tidy` changes
only the quic-go requirement and its two checksum entries; `go mod verify`
passes. The production `ListenEarly` / `http3.Server` lifecycle needs no source
adaptation. Shared TLS/mTLS policy, listener limits, Alt-Svc lifecycle and
explicitly disabled 0-RTT remain in force. No transport fork is introduced.

Relevant observable upstream changes checked with the existing HTTP/3 tests:

- Local stream closure now yields `quic.ErrStreamClosed`, including the stream
  context's cancellation cause, rather than `context.Canceled`.
- Leaving `InitialPacketSize` unset allows 1280-to-1200-byte fallback on
  `EMSGSIZE`; explicit packet-size floors retain different behavior.
- Congestion recovery, migration/MTU discovery and candidate-path handling
  change internally. The existing tests are regression evidence, not an
  exhaustive network-impairment or MTU test. No additional soak was run.
