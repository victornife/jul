# Adversarial design and implementation review ledger — #621 (`CACHE-OPS-01`)

> Date: 2026-10-25 · Scope: #621 scoped URL, prefix, pattern, tag, and hostname cache invalidation ([ADR 0027](../adr/0027-scoped-cache-invalidation.md)) · Programme: #62 / Epic #620

## Review programme structure

Per the #621 delivery contract, independent read-only `rubber-duck` subagents
reviewed the work in two stages:

1. **Stage 1 — Pre-implementation adversarial design review** (`design-review-0027`,
   agent `54803aa0-66ba-4621-aba8-1c9448c4759b`, 2 turns): challenged
   [ADR 0027](../adr/0027-scoped-cache-invalidation.md) before shared-architecture
   implementation. All 7 blocking and 2 non-blocking design findings (`D-01`
   through `D-09`) were resolved and re-verified before implementation began.
2. **Stage 2 — Six-lane integrated implementation review and re-audit:**
   - **Lanes 1 & 2** (`review-lanes-1-2`, agent `1f986e8e-92ca-4e26-8a9a-87aff2594c71`):
     Architecture, ownership, compatibility, successor contracts (#622/#624),
     selectors, normalization, origin grouping tags, and cross-scope isolation.
   - **Lanes 3 & 4** (`review-lanes-3-4`, agent `b3308aa1-a26d-4fbf-859a-31c4eb3a02f4`):
     Fill/revalidation concurrency, linearization, reload, active reader leases,
     disk durability, crash recovery, resource bounds, and performance.
   - **Lanes 5 & 6** (`review-lanes-5-6`, agent `632167f2-2167-494e-b244-a012805f90c4`):
     Admin API, CLI, RBAC, audit, operation states, retry/idempotency, Console
     usability/accessibility, documentation, and test quality.
   - **Adversarial re-audit** (`re-audit-all-lanes`): re-verified all 18
     implementation findings and their regression tests across Lanes 1–6.

| `D-04` | P1 | `demonstrated_defect` | Unconditional `h.Del(tagHeader)` in `cacheWriter.WriteHeader` could clobber a header set by an outer middleware layer; conversely, `strip_tag_headers = true` must never leak configured tag headers downstream. | Configured `tag_headers` rejects reserved HTTP headers (`ETag`, `Cache-Control`, `Vary`, etc.) and strips configured tag headers across miss, hit, range, and revalidation paths when `strip_tag_headers = true`. | `D-05` | P1 | `demonstrated_defect` | `304 Not Modified` responses omitting `Cache-Tag` vs carrying an updated `Cache-Tag` needed deterministic tag merge semantics. | Defined `mergeEntryTagsOn304` in `internal/cache/merge.go`: omitted tag header preserves stored tags; present tag header replaces stored tags; invalid tag header triggers `mergeDiscard`. | Resolved & Verified |
| `D-06` | P1 | `demonstrated_defect` | Partial disk deletion of a `Vary` group before a crash could leave orphaned variant files on disk after restart. | Added `pruneOrphanedVaryStubsLocked()` in `internal/cache/diskstore.go` during `rehydrate()` to remove any variant whose base `Vary` stub is absent or does not claim it. | `D-07` | P1 | `demonstrated_defect` | If both disk file unlink and `.jul-cache-tombstones` write fail, reporting `incomplete` understated restart resurrection risk. | Added `invalidation_effective = "uncertain"` and `unrecoverableInvalidation` fail-closed disk-hit disablement when tombstone persistence fails. | `D-09` | P2 | `substantiated_risk` | In-memory idempotency ledger was lost across process restart even when `[cache].disk_path` was configured. | Persisted bounded `.jul-cache-purge-ledger` in `[cache].disk_path` (`internal/admin/apiv1_cache.go`). Verified in `TestV1CachePurgeWorkflowRBACBindingIdempotencyAndSecretSafety`. | Resolved & Verified |
