# v2.2.0 GA decision: routing, resilience and auxiliary egress

> This is the original publication decision. The then-pending post-GA gate
> subsequently completed on 2026-10-14 under the
> [source-bound eight-hour #590 review](2026-10-14-ga-soak-590-results.md),
> which retains the original collector failure and authorised supplement.

The maintainer selected all three promotions under #527 on 2026-10-12.
The decision covers the bounded implementations already released in v2.0.0,
not full NGINX parity, new retry outcomes, distributed state or a new security
boundary. Publication and maturity remain separate.

## Decisions and contracts

| Feature | Decision | Stable surface | Remaining boundary |
| --- | --- | --- | --- |
| CGC-ROUTE | GA, soak pending | Existing method/header/query predicates, matching precedence, ordered response headers and bounded CORS/preflight; documented keys, defaults, wire headers/statuses and lifecycle semantics | No arbitrary expression language, new predicate language or full NGINX equivalence; later optional additions do not automatically inherit this certification |
| CGC-RES | GA, soak pending | Existing per-pool admission/pending controls, backend capacity, retry/deadline/backoff/budget and circuit state/accounting; config, bounded metrics and documented failure semantics | No outcome-aware retry expansion, shared fleet quotas or replay of an active streaming call; raw configuration remains the advanced editing path |
| SEC-EGRESS | GA, soak pending | Existing enabled/allow configuration, auxiliary-fetch dial-time enforcement, redirect/DNS rules, generation ownership and bounded denial labels | Not a global firewall or complete SSRF filter; trusted-name DNS rebinding and backend traffic remain the documented exclusions |

These surfaces enter the v2 stable contract in
[compatibility.md](../compatibility.md#v220-ga-contract-certification).
Breaking changes require a MAJOR version and the existing deprecation process.
MINOR additions must retain accepted keys, documented defaults, labels and wire
semantics. Invalid inputs are not frozen as a compatibility guarantee.
The immutable v2.2.0 source/tag will be the published baseline; no tag is moved.

## Evidence and operability

- Configuration contract: source-owned config schema/value/lifecycle inventories
  and their drift tests; `TestGA220ExistingConfigurationContract` pins the three
  surfaces' accepted config, opt-in defaults and schema/parse round-trip.
- Routing: existing precedence differential, predicate, response-policy and CORS
  tests, published core-HTTP benchmarks, limitations and threat notes. Route
  configuration/Status and route-test diagnostics remain the operator surfaces.
- Resilience: existing cross-protocol admission/retry/circuit tests, failure
  attribution/fuzz coverage, published queue-memory/retry measurements and
  limitations. Apps shows backend circuit reasons; the App detail resilience
  section now reads the existing API's effective limits, active/pending pressure,
  eligibility, circuit states and retry allowance. Config links provide the
  authoritative expert editing path. Missing/failed readback is unavailable,
  not healthy zero; exhausted and disabled budgets remain distinct.
- Egress: existing deny/allow, DNS/redirect and generation-replacement tests,
  threat notes and configuration validation. Security reports enablement, rule
  count and bounded recent denials. No destination history is introduced.
- Metric schemas retain their released compatibility guard. Unversioned Console
  readback remains internal; no new supported external API is asserted.

Focused tests and exact-head CI must pass before merging this decision. The
decision does not claim new measurements or a new security audit. Existing
feature evidence keeps its original source identity.

## Post-GA stability gate

Criterion 5 remains false for these three rows. ADR 0005 permits GA with an
explicit pending post-GA soak gate; the manifest uses `GA-soak-pending` and
`released`, not `soaked`. This release task does not run a new long-duration
campaign and does not relabel consolidated/historical measurements as these
features' soak. A later explicitly selected feature run follows the existing
minimums, with its source, workload, duration and verdict recorded separately.
Any applicable soak regression remains release-blocking. The existing short
release-smoke workflow is unchanged and is not long-running GA evidence.

## Release boundary

v2.2.0 includes the selected remediation/security/correctness work and optional
features. Go 1.27.2 requires macOS 13+, with the documented HTTP header-value,
JSON, compression and TLS compatibility details carried into release notes.
The seven exact HTTP/3 exceptions owned by #569 remain narrow, source/tool-bound
and visible; allow-listed green checks do not mean complete RFC conformance.
Package identity, signed attestations, actual supported-host startup and upgrade
checks are required before publication. No overall-coverage target is changed.
