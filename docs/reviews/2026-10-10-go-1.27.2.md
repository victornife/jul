# Go 1.27.2 upgrade review

Date: 2026-10-10. Starting source: `2eb71cee4fed3838474d826a40e211e49677de39`.
Related owners: #62 (programme), #539 (HTTP/2 residuals), #509 (container/release
toolchain parity), #430 (plugin ABI compatibility).

## Scope and compatibility decisions

The root and example guest modules now require Go 1.27.2. CI and release
workflows read the root directive; the Docker builder uses the matching
`golang:1.27.2-alpine` manifest-list digest
`sha256:f92b6ef800e499660581efdabdf25d9d817a9d124eaf900924f0504e7e27e12d`,
verified against the public registry. The bundled FastCGI replacement keeps its
own Go 1.21 minimum. `go mod tidy` changes no dependency version or checksum.

The previous golangci-lint v2.12.2 binary was built with Go 1.26.2. CI now pins
v2.14.0, whose published Linux binary is built with Go 1.27.0 and accepts this
module. Linter rules, exclusions and coverage floors are unchanged.

The six platform combinations and lean/full release profiles remain. Go 1.27
raises the macOS runtime minimum to **macOS 13 Ventura**. Published packages,
their build identities and historical benchmark/soak evidence are unchanged.
This work prepares a future release: **no soak is required or claimed here**,
and no feature maturity or release tag changes.

Upstream changes were reviewed against the [Go 1.27 release
notes](https://go.dev/doc/go1.27):

- HTTP/1 and bundled HTTP/2 now apply Go's default 500 header-value cap as well
  as `max_header_bytes`. Repeated field lines count separately, including the
  individual names in comma-separated `Trailer` declarations. No Jul knob is
  introduced, no byte limit is increased, and this is not an HTTP/3 guarantee.
  `TestHeaderValueCountLimitBeforeHandler` checks real HTTP/1 and h2c Jul
  listeners: a small over-count list is rejected before the handler and a
  subsequent healthy request succeeds.
- HTTP/2 client priorities, HTTP/1 response-body draining/connection reuse,
  ALPN on compatible wrapped connections, JSON implementation/error text and
  changed DEFLATE bytes are exercised through the existing protocol, handler,
  contract, compression and lifecycle suites. There is no bulk JSON/v2 API,
  generic-method or protocol-adapter migration.
- `goroutineleak` is now a stdlib pprof profile. Tests verify that its inherited
  admin route requires `admin:manage`, respects the TLS-or-loopback transport
  gate and returns 404 when `admin.pprof` is false. The route catalog and
  external Admin API contract do not gain a new endpoint.
- No removed timer/debug/experimental switch is configured by the repository.
  There is no permanent opt-out from the new runtime or JSON implementation.

## WASM build and ABI evidence

All ten examples compile from source as `wasip1/wasm` reactors with Go 1.27.2;
guest vet and the native signed-URL policy/signer tests pass. The native policy
has 100% statement coverage and signer 95.8%. The fresh-build ABI, negotiation,
request/response, handler and signed-URL integration suites pass.

Only `v1-current-header-inject.wasm`, `v2-status-header.wasm`, `v2-redact.wasm`
and `testguest-v2.wasm` are regenerated. Historical v1 guests and both ABI
goldens remain byte-identical. Existing supported v1/v2 user guests do not need
rebuilding or a configuration ABI change.

## Verification and source-bound evidence

Local host: Linux amd64; Go 1.27.2, golangci-lint v2.14.0. The Go archive and
linter archive were checked against their published SHA-256 values. Full-tag
build and vet, guest vet, fresh plugin execution and lint pass.

The local repository-wide lean run encounters the environment's denied Unix
socket operations and unavailable process RSS/FD/CPU collectors. These are not
skipped or weakened; hosted CI is the authority for the complete platform,
race, security, coverage and deployment suites. The upgrade's profiler and
header-count regressions pass locally.

Protocol conformance now also runs for PRs changing either Go module, the root
checksum file, suite harness, allow-list or workflow. Its external h2spec, HTTP/3, Autobahn, cache and
framing reports remain independently retained. #539 stays open until its exact
residual cases are rechecked; an upgrade alone is not evidence of closure.

Local pinned h2spec v2.6.0 (`70ac2294010887f48b18e2d64f5cccd48421fad1`)
rechecks the four TLS/h2c static/proxy targets: **566/584 passed**, the same
five historical groups and 18 allowed target failures, **zero unexpected and
zero stale entries**. TLS targets pass 142/146 each; h2c targets pass 141/146
each. The framing corpus passes **27/27**. #539 remains open; neither the
allow-list names nor their target scopes change. Original Go 1.26.8 source
rationales and the prior comparison report remain historical evidence.

The first hosted run exposed two existing harness problems. Autobahn's
malformed-frame cases caused passive ejection of its single echo backend,
turning later cases into HTTP 503s. Its test-only pool now keeps that backend
available between independent cases, as the cache suite already does.
The pinned h3spec output contains ANSI colours and duplicate example names;
the parser now retains every example and rejects incomplete/inconsistent
output. Regression tests verify both properties. A controlled local comparison
of the starting source built with Go 1.26.9 and the upgraded source built with
Go 1.27.2 produces **42/49** on both, with the exact same seven failing case
IDs and no additions or removals. One 0-RTT example is reported by the tool as
passing after printing a skip warning, so that behavior is not claimed tested.
These inherited HTTP/3 failures remain visible; no new conformance exceptions
are added here, and the external lane is not claimed green.

Hosted PR results and any additional local benchmark observations
are recorded on the PR and the related issues with the tested commit identity.
Existing whole-repository and package coverage requirements are preserved;
this upgrade does not introduce a 90% whole-repository target.

## NGINX migration impact

**Not applicable to directive translation:** no new configuration key,
translation rule, candidate disposition or importer default is introduced.
Runtime HTTP changes are still relevant to already-imported traffic; the
existing corpus and pinned reference E2E run under the upgraded toolchain.
The header-count boundary is documented explicitly rather than represented as
an equivalent NGINX byte-size directive. No residual conformance allow-list is
broadened and no new equivalence is claimed.
