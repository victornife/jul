# v2.2.0 release preparation

The maintainer selected v2.2.0 after the completed Wave 1/2 remediation and
approved #527's independent bounded GA decisions. Runtime scope is frozen;
this release adds no new candidate, long-running soak campaign or overall
coverage target. The release workflow and its short smoke gate remain binding.

## Release contents

- Admin readback/diagnostic confidentiality fixes and attributable operations
  from #514, with coordinated private-advisory version/disclosure records.
- Downstream write-inactivity timeout with explicit HTTP/1 byte-progress versus
  HTTP/2/3 per-operation boundaries; long-lived reload/shutdown documentation
  and exactly-once graceful/forced resource-retirement metric wiring.
- Optional bounded per-route RED/bytes metrics and Console charts, plus
  process-start generation-retirement totals with unavailable/reset handling.
- Faithful signed plain-duration response expiration, scoped configurable MIME
  and bounded NGINX idiom/importer translation with pinned reference evidence.
- Health probe headers/Host and independent gRPC routing authority; signed-URL
  WASM recipe and native issuer, with key rotation and real-clock enforcement.
- Go 1.27.2 and dependency security/correctness updates.
- Existing routing/CORS, resilience and auxiliary-egress contracts promoted
  independently to GA with explicit pending post-GA soak; bounded resilience
  Console readback closes its operability gap.

Other Beta capabilities keep their maturity. The full feature matrix and
[GA decision](../reviews/2026-10-12-ga-220.md) remain authoritative.

## Compatibility and upgrade

**Darwin packages require macOS 13 Ventura or later.** The Go 1.27 toolchain
also introduces the documented HTTP/1/2 500-header-value limit independent of
`max_header_bytes`, updated HTTP/2 priorities/HTTP body draining, JSON error
wording and compression-output changes, and platform trust-store environment
overrides. These are covered by the [Go upgrade review](../reviews/2026-10-10-go-1.27.2.md)
and [compatibility policy](../compatibility.md#supported-build-toolchain-and-platforms).
Exact JSON error text and compressed bytes are not promised wire contracts.
Operators relying on `SSL_CERT_FILE` or `SSL_CERT_DIR` on Windows/Darwin should
review Go's platform-verifier override behavior.

The seven exact temporary HTTP/3 exceptions owned by #569 remain in force.
Record raw 42/49 h3spec results alongside the seven allowed failures; preserve
the skipped 0-RTT warning. The allowed green lane does not mean full HTTP/3 RFC
conformance, a new Go regression or an established exploit. Review/remove each
entry on dependency/tool changes; there is no wildcard suppression or Jul fork.

Before upgrading, run the **downloaded target binary** against the actual
configuration. Preserve the v2.1.0 binary, configuration and state backup;
rollback requires a configuration v2.1.0 accepts. New optional keys must be
removed/restored before rollback. Restart resets process-lifetime counters and
does not retain live connections; hijacked WebSockets have no guaranteed
Close-frame exchange at process exit. Existing raw-config/RBAC and TLS trust
boundaries remain intact.

## Immutable-source package acceptance

The final source is the commit referenced by immutable tag `v2.2.0`; preparation
baseline `83423f71` is not mislabeled as the final tagged source. After merging
the reviewed preparation PR, verify the final commit's required CI before
creating/pushing the tag. Never move the tag to repair a failed release.

The supported release workflow builds twelve OS/architecture/profile archives
and signed provenance/SPDX attestations, then creates a draft release. Before
publication, the native `Release package verification` workflow downloads those
actual archives and verifies:

1. Aggregate and individual checksums, embedded tag/source/clean-tree/platform
   identity and bundled SPDX, plus signed provenance and SBOM bound to the exact
   tag/commit and repository release workflow.
2. Native startup/config checks for lean/full, static/proxy responses,
   authenticated admin readiness/metrics and the full Console.
3. A v2.1.0-compatible configuration on the downloaded old binary, then target
   upgrade, then old-binary rollback. No source-rebuilt replacement substitutes
   for the package being certified.

Reports explicitly name all executed hosts. Unsupported/unavailable runners or
unexecuted packages are not marked passed. Package verification records will be
attached to the draft/release, not fabricated in this preparation document.

The two #514 advisories have privately verified affected versions and v2.2.0 as
the first patched release. Publish fixed downloads only after these checks,
then disclose the approved advisories with accurate ranges; no private
reproduction narrative belongs in public programme comments. No CVE request
is selected. #527 closes through the GA decision PR, while #569 stays open.
